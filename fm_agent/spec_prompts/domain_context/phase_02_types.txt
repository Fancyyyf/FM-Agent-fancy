# Phase 2: Function Extraction & Call Graph Construction — Types and Invariants

## Overview

Phase 2 extracts functions from source files across multiple languages, parses
code into blocks, handles specification and info annotations, and constructs
inter-procedural call graphs from static analysis and user-supplied edges.

## Key Types

### `LANG_CONFIG` (extract.py)

Per-language configuration dict. Keys: `"c"`, `"cpp"`, `"python"`, `"go"`,
`"rust"`, `"java"`, `"typescript"`, `"javascript"`, `"erlang"`, `"cuda"`, `"arkts"`.

Each value:
- `comment_prefix: str` — `"//"`, `"#"`, or `"%"`
- `spec_marker: str` — e.g. `"// [SPEC]"`
- `skip_prefixes: tuple[str]` — line prefixes to skip during extraction
- `skip_keywords_line: tuple[str]` — bare-keyword lines to skip
- `keywords: set[str]` — language keywords to exclude from function name detection
- `body: str` — block delimiting style: `"brace"`, `"indent"`, or `"external"`

### `EXT_TO_LANG` (extract.py)

Extension-to-language mapping:
```
cpp/cc/cxx/c/h/hpp → "cpp"  (except .c → "c")
py → "python", erl → "erlang", go → "go", rs → "rust"
java → "java", ts/tsx → "typescript", js/jsx → "javascript"
cu/cuh → "cuda", ets → "arkts"
```

### Extracted Function Representation

Functions extracted as `(deduped_name: str, source_text: str)` tuples.

**Naming rules:**
- Class-qualified identifiers (`"LocalStorage::Flush"`) keep `::` in filenames.
- Duplicate names within a file get `_1`, `_2`, etc. suffixes after canonicalization.
- Function directory is `<base>-<ext>` (last dot → hyphen): `loader.cpp` → `loader-cpp/`.
- Output path: `extracted_functions/<src_dir>/<base>-<ext>/<func_name>.<ext>`

**Invariants:**
- `_safe_filename` replaces `/` with `_` but preserves `"::"` for class qualifiers.
- `_validate_extraction` re-parses each extracted file, warns if ≠ 1 function.
- On resume, files with both `[SPEC]` and `[INFO]` are skipped.

### `FunctionSpecMap` (parser.py)

Dict subclass mapping function names to specs:
- `signatures: dict[str, str]` — function name → signature line
- `add_entry(function_name, signature, spec)` — registers a callee entry

### `parse_input_function(file_path)` Return Value

Parses specced function file into three parts:
- `func: str` — source code after [INFO] block, comments stripped,
  each line prefixed `"Line N: "` (1-indexed)
- `nl_spec: str` — text between two `[SPEC]` markers
- `knowledge: FunctionSpecMap` — callee specs parsed from `[INFO]` block

**Marker regexes:**
- `[SPEC]` / `[INFO]`: `^\s*(?:(?://+|#+|--+|%+)\s*)?\[(SPEC|INFO)\]\s*$`
- `[SPLIT]`: `^\s*\[SPLIT\]\s*$` (separates callee entries in [INFO])

**Invariants:**
- `[SPEC]` block has exactly two markers (opening and closing).
- `[INFO]` block has exactly two markers; content split by `[SPLIT]`.
- Each [INFO] entry starts with a function signature; `_extract_function_name`
  extracts name before first `(`.

### `CallEdge` / `CallerSelector` / `CalleeTarget` (call_graph_edges.py)

**`CallerSelector`** (frozen dataclass):
- `fqn: str` — exact caller FQN or empty string
- `callsite_names: tuple[str, ...]` — source callsite tokens

**`CalleeTarget`** (frozen dataclass):
- `fqn: str` — exact callee FQN (required, non-empty)
- `info_names: tuple[str, ...]` — metadata for [INFO] matching

**`CallEdge`** (frozen dataclass):
- `caller: CallerSelector`
- `callee: CalleeTarget`
- `source: str` — provenance

**FQN Normalization:**
`normalize_fqn_label(label)` converts `path/to/file.c::func` to FM-Agent FQN
by stripping `./`, extracting base filename, replacing last `.` with `-`,
joining with `::`.

## Extraction Algorithm Details

### Brace-delimited (`_extract_functions_brace`)
For C, C++, Java, Go, Rust, JS, TS, CUDA, ArkTS:
1. Skip blank lines, block comments (`/* */`), preprocessor directives, keyword lines.
2. Detect function signatures: lines with `(` not ending with `;`.
3. Go: `func` keyword. Rust: `fn` keyword (excludes `#[test]`-annotated).
4. Brace matching via `_find_brace_end`: respects strings, chars, `//` comments,
   and Go anonymous composite types (`interface{...}`/`struct{...}`).

### Indent-based (`_extract_functions_indent`)
For Python: match `def <name>(` at any indent; include decorators; body extends
to first line at same/lower indent.

### Codegraph-backed (`_function_spans`)
When codegraph indexes the file, boundaries come from codegraph; else falls back
to regex extraction. Both yield same `(name, start_idx, end_idx)` shape.

## Entry Points

### `extract_functions_from_file(filepath, lang_key) → list[(str, str)]`
Returns `(function_name, source_text)` tuples for all functions in a file.

### `run_extraction(proj_dir, work_dir, force, verbose) → (int, int)`
Main extraction driver. Reads phases.json, extracts functions, writes to
`extracted_functions/`, validates. Returns `(written, skipped)`.

### `parse_input_function(file_path) → (str, str, FunctionSpecMap)`
Parses specced file into code body (with line numbers), spec text, callee map.

### `load_call_edges(path) → list[CallEdge]`
Loads supplemental call edges from JSON file or directory, deduplicating.
