# Phase 4: Specification Generation & Code Reasoning — Types and Invariants

## Overview

Phase 4 generates behavioral correctness specifications via LLM agents (using
[SPEC] and [INFO] blocks) and performs block-by-block Hoare-style reasoning
to verify code against specifications.

## Key Types — Prompts (prompts.py)

### Spec Check Verdict

Structured JSON verdict from the spec-check LLM:
```json
{
  "verdict": "MATCH" | "MISMATCH",
  "counterexample": string | null,
  "offending_statements": string | null,
  "reason": string
}
```

**`_parse_spec_check_json(response) → (bool, str|None, str|None, dict)`:**
Returns `(has_violation, offending_statements, reason, parsed_dict)`.

**Validation:**
- `verdict` must be exactly `"MATCH"` or `"MISMATCH"` (case-insensitive input).
- MISMATCH: all three evidence fields must be non-empty strings.
- MATCH: counterexample and offending_statements must be null/empty.
- `offending_statements` must preserve `"Line N:"` prefixes.
- Retries up to `MAX_SPC_ITER` (default 5) on format errors.

### Post-Condition Generation

Returns: `{"post_condition": "non-empty string"}`

**`_parse_post_condition_json(data) → str`:** Returns non-empty post_condition.

### Language Expertise (`_LANGUAGE_EXPERTISE`)

Per-language system prompts for the spec-check LLM. Covers: Rust, C, C++,
Python, Java, Go, C#, Kotlin, Swift, PHP, Ruby, Scala, Dart, CUDA,
JavaScript, TypeScript, Erlang, ArkTS. Each encodes version-specific knowledge
of type systems, standard libraries, and semantics.

### LLM Message Construction

**`_generate_block_post_condition(block, pre_condition, knowledge, language, ...) → str`:**
System: expert in formal verification. User: language, pre-condition, code block,
optional callee context. Returns post-condition text.

**`_check_post_implies_spec(block, post_condition, spec_post_condition, knowledge, language, ...) → (bool, str|None, str|None, str|None)`:**
System: language expertise + violation detection rules (missing cases, wrong
outputs, invalid acceptance). User: language, code block, actual post-condition (A),
spec post-condition (B), optional callee context. Returns verdict tuple.

## Key Types — Reasoner (reasoner.py)

### Block Splitting

**`_split_into_blocks_braced(func, language) → list[str]`:**

For non-Python languages, splits respecting brace depth:
1. Strip `"Line N: "` prefixes.
2. Compute brace depth per line (respecting strings, chars, comments).
3. Determine entry depth (first positive depth, or 0).
4. Greedy safe splitting: from GRANULARITY-sized candidate, find next line
   at entry depth, split there.

**`_split_into_blocks(func)` (Python fallback):**
Simple line-count: blocks of `GRANULARITY` lines, remainder absorbed.

**Invariants:**
- `GRANULARITY` (default 40) controls minimum block size.
- Split only at entry-depth lines (close of top-level constructs).

### Terminating Statement Detection

`_TERMINATING_PATTERNS` maps language → regex:
```
rust:   return|panic!|std::process::exit|unreachable!
c:      return|exit|_Exit|abort|longjmp
c++:    return|exit|_Exit|abort|throw|std::terminate|std::exit
python: return|sys.exit|raise|exit|quit
cuda:   return|exit|_Exit|abort|__trap
java:   return|throw|System.exit
go:     return|panic|log.Fatal|os.Exit
js/ts:  return|throw|process.exit
erlang: throw|exit|error|erlang:error|erlang:exit
...
```

### Spec Parsing

**`_parse_spec_conditions(spec) → (str|None, str|None)`:**
Extracts `Pre-condition:` and `Post-condition:` sections from spec text.

### Reasoner Core

**`reasoner(func, spec, info, language, trace_context=None) → str`:**

Algorithm:
1. Parse pre-condition and post-condition from spec.
2. Split function into blocks (≥ GRANULARITY lines).
3. For each block sequentially:
   a. Generate post-condition via LLM (`_generate_block_post_condition`).
   b. If block has terminating statement OR is last block:
      Check if post-condition implies spec via LLM (`_check_post_implies_spec`).
   c. If MISMATCH: return failure with statements, post-condition, reason.
   d. Set `current_pre = post_condition` for next block.
4. All blocks pass: return success.

**Return strings:**
- Success: `"The function passes the verification..."`
- Parse failure: `"Failed to parse pre/post conditions..."`
- LLM failure: `"Failed to generate post-condition for block N."`
- Mismatch: `"Verification FAILED.\nStatements triggering...\nPost-condition...\nReason..."`

**Invariants:**
- Function body must start with `"Line N: "` prefixes (from `parse_input_function`).
- `_sanitize_strings` strips non-ASCII characters from all string values in
  dicts/lists before writing to JSON.
- All LLM calls are traced with: function_id, function_file, language,
  block_index, block_count.

### `_compute_brace_depth_per_line(lines) → list[int]`

Returns brace depth after each line, respecting: string literals, char literals,
`//` line comments, `/* */` block comments.

## Entry Points

### `reasoner(func, spec, info, language, trace_context=None) → str`
Main reasoning function. Returns verdict string.

### `_generate_block_post_condition(block, pre_condition, knowledge, language, ...) → str`
LLM call for one block's post-condition.

### `_check_post_implies_spec(block, post_condition, spec_post_condition, knowledge, language, ...) → (bool, str|None, str|None, str|None)`
LLM call to check post-condition against spec. Returns verdict tuple.
