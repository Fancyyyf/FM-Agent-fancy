# Phase 04 — LLM Communication & Tracing

## Core Types

### LLM Client (`llm_client.py`)

**LLM Call Pattern:**
- Primary path: OpenAI-compatible API via `openai` SDK client
- Anthropic-native path: detected via model name prefix (`claude`/`anthropic/`), routed to `/v1/messages`
- JSON response parsing: `_parse_json_response()` handles direct JSON, fenced blocks, and prose-wrapped structured responses
- Retry: exponential backoff with jitter for rate limits (up to 20 retries), general errors (up to 5 retries)

**Key Functions:**
```python
def build_llm_cli_command(model, prompt, cwd, files=None) → list[str]:
    """Build CLI command for file-oriented LLM task.
    CLI backends: codex exec / claude command
    Default: opencode run --model <provider>/<model> --file ... -- <prompt>
    """

def _llm_json_call(messages, model=None) → dict:
    """Send messages via OpenAI API, parse response as JSON. Returns dict on success."""

def _parse_json_response(response) → dict | list:
    """Parse structured JSON from LLM response text.
    Handles: bare JSON, ```json fences, prose-wrapped JSON objects.
    Raises ValueError on failure."""

def _retry_create(client_callable, *args, **kwargs) → tuple:
    """Call with exponential backoff retry. Returns (text_response, usage_dict)."""
```

**Request Injection:**
```python
def _should_inject_user_id(base_url) → bool:
    """Whether to inject user_id metadata header for prompt-cache affinity."""
```
Uses `settings.inject.id` (or built-in fallback) and `settings.inject.hosts` (comma-separated).

**Anthropic Native Adapter:**
```python

    """Split OpenAI messages → (system_text, anthropic_messages).

### Trace Writer (`trace_writer.py`)

**File Layout:**
```
fm_agent/trace/
├── events.jsonl       # structured event records (newline-delimited JSON)
├── payloads/          # event payloads (stdout, LLM messages, responses)
│   ├── <event_id>_opencode.log
│   ├── <event_id>_message_00_system.txt
│   ├── <event_id>_message_01_user.txt
│   └── <event_id>_response.txt
└── opencode/          # raw LLM request/response pairs (plugin-generated)
    └── <event_id>.jsonl
```

**Event ID format:** `evt_<uuid4_hex>`

**Event Record Shape:**
```python
{
    "event_id": str,         # e.g. "evt_a1b2c3..."
    "timestamp": str,        # ISO 8601 UTC
    "stage": str,            # pipeline stage
    "command": [str],        # full argv
    "exit_code": int,
    "duration_s": float,
    "function_ids": [str] | None,
    "input_files": [str] | None,
    "output_files": [str] | None,
    "metadata": {...},
    "children": [
        {
            "type": "system_prompt" | "user_prompt" | "assistant_output",
            "role": str,
            "content_ref": str,  # relative path to payload file
        }
    ]
}
```

### Prompts (`prompts.py`)

**Spec-Check JSON Parsing:**
```python
def _parse_spec_check_json(response) → tuple:
    """Parse and validate spec-check LLM response.
    Returns (has_mismatch: bool, offending_statements: str, reason: str, data: dict).
    
    Required JSON fields: {verdict, counterexample, offending_statements, reason}
    - verdict: "MATCH" | "MISMATCH" (case-insensitive, normalized to uppercase)
    - MATCH: counterexample and offending_statements must be null/empty
    - MISMATCH: all three fields required (non-empty strings)
    Raises ValueError on schema violations."""

def _generate_block_post_condition(messages, model=None) → str:
    """Generate Hoare-style post-condition for one code block via LLM."""

def _check_post_implies_spec(messages, model=None) → tuple:
    """Check whether block post-conditions jointly imply the function spec.
    Returns (has_mismatch, offending_statements, reason, data)."""
```

**JSON Parse Utility:**
`_parse_json_response(response)` is the shared parser used across the codebase.
It extracts JSON from LLM output handling: bare JSON objects/arrays, markdown-fenced
code blocks (` ```json `), and prose-wrapped structured text.

## Invariants

1. All LLM calls through `llm_client.py` MUST use retry logic — no bare API calls.
2. `_llm_json_call` and `_parse_spec_check_json` MUST handle malformed JSON gracefully
   (ValueError, not crashing the pipeline).
3. Trace events are NO-OP when `trace_dir` is falsy — tracing is always-on but safe to disable.
4. Thread-safe event writing uses `threading.Lock` on the events.jsonl append path.
5. CLI backend resolution through `resolve_model_backend()` is the single source of truth
   for all callers — no ad-hoc backend checks elsewhere.
6. `OPENCODE_CONFIG_CONTENT` is OpenCode's highest-precedence config — injected
   provider blocks override same-named providers in the user's opencode.json.
7. `_parse_json_response` is the single shared JSON extraction function — all spec-check,
   post-condition, and validation callers use it.
