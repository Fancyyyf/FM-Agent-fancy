# Phase 3: Scope Analysis & Layer Organization — Types and Invariants

## Overview

Phase 3 has two responsibilities: (1) function-level localization for incremental
mode (heuristic scoring + optional LLM re-ranking), and (2) building dependency-ordered
top-down layers from intra-phase call graphs for batch prompt generation.

## Key Types — Scope Analysis (scope.py)

### Signal Extraction

**`_parse_issue_signals(issue_text) → dict[str, set[str]]`:**
- `traceback_funcs` — T1: Python traceback function names (×10)
- `backtick_idents` — T2: backtick/code-block identifiers (×5 name, ×2 body)
- `dotted_refs` — T3: method names from Class.method refs (×15)
- `dotted_classes` — T3: class names from Class.method refs
- `plain_idents` — T4: CamelCase/snake_case in prose (×3)
- `exception_types` — T5: exception type names (×4)
- `all_words` — T6: all alphabetic words ≥ 4 chars, not in `_STOP` (×1)

### Per-Function Info Dict
```python
{
    "name": str,        "start": int,       "end": int,
    "calls": set[str],  "idents": set[str],
    "body_words": set[str],  "exc_types": set[str],
    "docstring": str,   # Python only
}
```

### Score Enrichments

**Call-graph propagation (intra-file):**
- `CALLEE_INHERIT = 0.30` — callee of high-scoring function gets 30% of its score
- `CALLER_INHERIT = 0.20` — caller of high-scoring function gets 20% of its score

**Class-scope narrowing (Python only):**
- `W_CLASS_NAME_MATCH = 6.0` — per token overlap: class name × intent
- `W_CLASS_DOC_MATCH = 2.0` — per token overlap: class docstring × intent
- `CLASS_METHOD_INHERIT = 0.40` — fraction of class score to each method
- `CLASS_BOOST_CAP = 8.0` — hard cap on per-method class bonus

### LLM Re-ranking

Triggers when: file has ≥ `LLM_TRIGGER_FUNCS` (default 5) unique functions,
OR top heuristic score < `LLM_CONFIDENCE_THRESHOLD` (default 8.0).

**Input:** `"<name> | <signature> | <docstring first line>"` per function.
**Output:** `["func_name_1", ...]` JSON array.
Falls back to heuristic on failure (3 attempts with backoff).

### `rank_functions_in_file()` Return
```python
list[dict]  # each: {"file", "name", "lineno", "end_lineno", "score", "reason"}
```
`reason` ∈ `{"heuristic", "llm", "heuristic_pad"}`.
Capped at `TOP_K` (default 5).

## Key Types — Top-Down Layers (generate_topdown_layers.py)

### Call Graph Construction

**`_build_call_graph()` returns:**
```python
(
    callees_map: dict[fqn, set[fqn]],     # within-phase callees
    callers_map: dict[fqn, set[fqn]],     # within-phase callers
    all_callees_map: dict[fqn, set[fqn]], # any phase
    file_map: dict[fqn, filepath],
    module_map: dict[fqn, module_name],
    edge_aliases_map: dict[callee_fqn, dict[caller_fqn, set[alias]]],
)
```

**Edge resolution:**
- Codegraph: precise `caller_fqn → callee_fqn`; only extracted callees kept.
- Regex fallback: bare-name call sites resolved to every same-named FQN.
- Supplemental edges: resolved via `_resolve_extra_call_edges` into
  `by_caller_fqn` (exact) and `by_callsite` (callsite name match).

**Call-site regex patterns:**
- C/C++/Java/JS/TS/CUDA/ArkTS: `\b(\w+)\s*(?:<[^>]*>)?\s*\(`
- Rust: `\b(\w+)\s*(?:::<[^>]*>)?\s*\(` (turbofish)
- Go: `\b(\w+)\s*(?:\[[^\]]*\])?\s*\(` (type params)

### Layer Computation

**`_compute_layers(phase_fqns, callees_map, callers_map)`:**
Returns `list[{"layer": int, "functions": list[str], "cycle_resolution": bool}]`.

Algorithm:
1. Kahn's algorithm: find functions with all same-phase callers already assigned.
2. On cycle: compute SCCs via iterative Tarjan's, build SCC DAG, topologically sort.
3. SCCs with >1 node: `cycle_resolution: True`.

**Invariant:** For any function F with phase-internal callee C, C's layer ≤ F's layer.

### Top-Down Layer Output
Written to `spec_prompts/phase_NN_topdown_layers.json`:
```json
{
  "phase": N, "phase_name": "...",
  "total_functions": N, "total_layers": N,
  "layers": [{
    "layer": 0, "cycle_resolution": false,
    "functions": [{
      "name": "fqn", "file": "extracted_functions/...",
      "unit": "module", "phaseN_callers": [...],
      "phaseN_callees": [...], "all_callees": [...],
      "phaseN_callee_info_names_by_caller": {...}
    }]
  }]
}
```

### Batch Prompt Types (generate_batch_prompts.py)

**`build_prompt()`** generates per-batch prompt files containing:
- Language/comment style, required reading files, key rules
- Earlier-layer caller specs (from lower layers)
- Callee expectations from callers' [INFO] blocks
- Cycle layer guidance (for mutual recursion)
- Function list with caller metadata, spec format template, process instructions

**Output:** `batch_NNN_layerM_extracted_bI.txt` or `..._cycle_bI.txt`
plus `manifest.json`:
```json
{
  "phase": N, "layers": "0-M",
  "total_functions": N, "total_batches": N,
  "batches": [{
    "index": 0, "file": "batch_000_layer0_extracted_b0.txt",
    "layer": 0, "is_cycle": false,
    "num_functions": 2, "num_pending": 2,
    "functions": ["fm_agent/extracted_functions/..."]
  }]
}
```

**`COMMENT_PREFIX_BY_LANG`:**
```
c/cpp/java/go/rust/javascript/typescript → "//"
python/ruby → "#", sql → "--", erlang → "%"
```
