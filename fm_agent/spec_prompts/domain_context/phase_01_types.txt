# Phase 1: Environment & Pipeline Setup — Types and Invariants

## Overview

Phase 1 initializes the runtime environment, validates prerequisites, generates
the analysis phase plan (`phases.json`), produces domain context files, manages
git worktrees, and provides shared LLM communication, trace, and CLI backend
infrastructure.

## Key Types

### `Settings` (config.py)

Central configuration object. Layered precedence: env > .env > fm-agent.toml >
built-in defaults. Contains subsections:

**Sections:**
- `LLMCfg`: `api_key: str`, `base_url: str`, `backend: str`, `name: str`,
  `effort: str`, `provider: str`, `api_style: Literal["openai", "anthropic"]`
- `RuntimeCfg`: `max_spec_iter: int` (≥1), `granularity: int` (≥1),
  `max_workers: int` (≥1), `opencode_max_retries: int` (≥1),
  `bug_validation_max_retries: int` (≥0), `opencode_timeout_s: int` (≥1),
  `domain_knowledge_paths: str`
- `ScopeCfg`: `top_k: int` (≥1), `llm_trigger_funcs: int` (≥1),
  `llm_top_k: int` (≥1), `llm_confidence_threshold: float` (≥0)
- `ErlangCfg`: `command: str`, `timeout_s: int` (≥1)
- `InjectCfg`: `id: str`, `hosts: str`
- `CodegraphCfg`: `repo: str`, `version: str`, `bin_dir: str`

**Invariants:**
- All integer fields with `gt=N` / `ge=0` are enforced by Pydantic validation
  at module load time; an invalid value raises `SystemExit`.
- Backward-compatible module-level constants (`GRANULARITY`, `MAX_WORKERS`,
  etc.) are derived from `settings` and exported via `__all__`.
- All stage-specific model selections (`OPENCODE_SETUP_MODEL`,
  `OPENCODE_SPEC_MODEL`, `OPENCODE_BUG_VALIDATION_MODEL`,
  `REASONER_POST_CONDITION_MODEL`, `REASONER_SPEC_CHECK_MODEL`) default to
  `LLM_MODEL` from the toml.

### `phases.json` Schema (pipeline_setup.py)

**Top-level object:**
- `project: str` — project name
- `languages: list[str]` — detected languages
- `file_extensions: list[str]` — detected extensions
- `phases: list[Phase]` — ordered list of phases

**Phase object:**
- `phase: int` — phase number (1-indexed, contiguous after cleanup)
- `name: str` — human-readable name
- `description: str` — prose description
- `modules: list[Module]`
- `depends_on_phases: list[int]` — phase numbers this phase depends on

**Module object:**
- `name: str`
- `description: str`
- `source_files: list[str]` — paths relative to project root

**Invariants:**
- After deduplication (`_deduplicate_phases`), each source file appears in
  at most one phase (earliest phase wins).
- After cleanup (`_clean_empty_phase_module`), empty modules/phases are removed
  and phases are renumbered 1..N contiguously.
- `_phase_plan_schema_errors` validates structural integrity (phases is a list,
  modules is a list, source_files is a list of strings).
- When `--submodule` filtering is active, out-of-scope files are stripped
  without renumbering.

### `CallEdge` / `CallerSelector` / `CalleeTarget` (call_graph_edges.py)

**`CallerSelector`:**
- `fqn: str` — exact caller FQN; empty if selecting by callsite
- `callsite_names: tuple[str, ...]` — source callsite tokens; any function
  containing one of these gets a supplemental edge

**`CalleeTarget`:**
- `fqn: str` — exact callee FQN (required, non-empty)
- `info_names: tuple[str, ...]` — metadata names for [INFO] matching

**`CallEdge`:**
- `caller: CallerSelector`
- `callee: CalleeTarget`
- `source: str` — provenance (edge file path)

**Invariants:**
- At least one of `caller.fqn` or `caller.callsite_names` must be non-empty.
- `callee.fqn` is a required non-empty string.
- Edges are deduplicated by `(caller.fqn, callee.fqn)` key; duplicate
  callsite_names and info_names are merged.

### Domain Context Files

**Output files:**
- `engine_overview.txt` — overall system architecture description
- `phase_NN_types.txt` — per-phase types, invariants, and entry points

**Invariants:**
- `_domain_context_complete` returns True only when `engine_overview.txt` and
  one `phase_NN_types.txt` per phase in `phases.json` all exist.
- `_setup_outputs_complete` requires both phase plan and domain context complete.

### Trace Event (trace_writer.py)

**Event shape (written to `events.jsonl`):**
- `event_id: str` — e.g. `"evt_deadbeef..."`
- `type: str` — `"opencode_call"` or `"llm_call"`
- `stage: str` — pipeline stage
- `status: str` — `"success"`, `"error"`, `"mismatch"`, `"format_error"`
- `start_time: str` — ISO 8601 UTC
- `end_time: str` — ISO 8601 UTC
- `summary: str`
- `metadata: dict`
- `children: list[dict]` — sub-event references with `type`, `role`,
  `content_ref` (relative path to payload file)

**Invariants:**
- Payload files are written via atomic tmp+os.replace (`write_payload`).
- `events.jsonl` writes are thread-safe (protected by `_LOCK`).
- LLM exchange events record all messages plus the raw response (when provided).

### `_StdoutTee` (incremental_reasoner.py)

Wraps sys.stdout to mirror bare `print()` output to both the console and
a file handler stream.

### CLI Backend Detection (cli_backend.py)

Detects available CLI backend (OpenCode, Codex CLI, or Claude CLI) and builds
appropriate command-line invocation strings.

## Entry Points

### `_run_setup_extract(proj_dir, work_dir, script_dir, ...)`
Main orchestrator for Phase 1+2: runs phase plan generation, post-processes
phases.json, and runs domain context generation.

### `_run_generate_phases(proj_dir, work_dir, script_dir, ...)`
Stage 1: reads `md/workflow_generate_phases.md`, invokes OpenCode agent to
produce `phases.json`. Supports resume, incremental mode, schema repair, retry.

### `_post_process_phases(proj_dir, work_dir, ...)`
Post-processes phases.json: ensures required files, filters to submodules,
deduplicates, cleans empty phases. Returns True if modified.

### `_run_generate_domain_context(proj_dir, work_dir, script_dir, ...)`
Stage 2: reads `md/workflow_generate_domain_context.md` and `phases.json`,
invokes OpenCode agent to produce domain context files.

### `build_llm_cli_command(model, prompt, cwd, files=None)`
Builds CLI command string for a file-oriented LLM task.
