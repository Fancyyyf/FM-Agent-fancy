# Phase 5: Bug Diagnosis & Verification — Types and Invariants

## Overview

Phase 5 orchestrates streaming reasoning across extracted functions, validates
specification mismatches, generates and executes probe scripts to reproduce bugs,
and produces structured bug reports with summary aggregation.

## Key Types

### Extended `EXT_TO_LANG` (verification.py)

Broader than extract.py's version:
```
.rs→Rust  .c/.h→C  .cpp/.cc/.cxx/.hpp→C++  .py→Python
.cu/.cuh→CUDA  .erl→Erlang  .java→Java  .go→Go
.cs→C#  .kt/.kts→Kotlin  .swift→Swift  .php→PHP
.rb→Ruby  .scala/.sc→Scala  .dart→Dart
.js/.mjs/.cjs/.jsx→JavaScript  .ts/.mts/.cts/.tsx→TypeScript
.ets→ArkTS
```

### Streaming Reasoner State

**`streaming_reasoner(input_dir, output_dir, file_list, proj_dir, work_dir,
poll_interval=2, spec_procs=None, already_processed=None, resume=False)`:**

Uses `ThreadPoolExecutor(max_workers=MAX_WORKERS)`. Maintains:
- `processed: set[str]` — completed file paths
- `expected_files: set[str]|None` — target files from file_list
- `submitted: set[str]` — in-flight files
- `reasoning_futures: dict[Future, str]` — in-flight reasoning
- `validation_futures: dict[Future, tuple]` — in-flight validation

**Algorithm:**
1. Scan input_dir for files with recognized extensions.
2. Skip: not in expected_files, already processed, already submitted,
   not `is_file_ready()`.
3. Submit ready files via `executor.submit(_verify_single_file, ...)`.
4. Non-blocking collection of completed reasoning futures:
   - MATCH/SKIPPED: mark processed.
   - MISMATCH: submit bug validation.
5. Detect spec process exit: if all spec processes exited before all
   files ready, log and break.
6. After all work: generate `summary.json`.

**Invariants:**
- Files only processed when `is_file_ready()` returns True.
- Resume skips files with existing parseable result JSON.
- Bug validation only when `proj_dir` is not None.

### Verification Result

**`_verify_single_file(file_path, input_dir, output_dir, language, work_dir, resume) → (str, str)`:**
Returns `(file_path, verdict)` where verdict ∈ `{"MATCH", "MISMATCH", "SKIPPED", "ERROR"}`.

**Output JSON** at `output_dir/<relative>.json`:
```json
{
  "function": "<path>",
  "verdict": "MATCH"|"MISMATCH"|"ERROR",
  "gaps": {
    "spec_claim": "<spec post-condition>",
    "actual_behavior": "<code's actual post-condition>",
    "code_evidence": "<offending statements>",
    "trigger_condition": "<reason>"
  }
}
```

MISMATCH gaps populated from reasoner output via regex:
- `actual_behavior`: `Post-condition:\n(.*?)\n\nReason for violation:`
- `code_evidence`: `Statements triggering the violation:\n(.*?)\n\nPost-condition:`
- `trigger_condition`: `Reason for violation:\n(.*)`

All string values sanitized via `_sanitize_strings`.

### Bug Validation

**`_validate_single_bug(result_json_rel, proj_dir, work_dir, resume)`:**
1. Derive `bug_id`: path components joined with `"--"`.
2. Read `md/bug_validator.md`, prepend target file + bug ID header.
3. Write per-bug prompt: `fm_agent/bug_validation/bug_validator_<bug_id>.md`.
4. Build CLI command, run via `run_opencode_traced`.
5. Resume: skip if `<bug_id>.result.json` exists and is valid JSON.
6. Retry up to `BUG_VALIDATION_MAX_RETRIES` (default 1).

**Expected output:** `<bug_id>.md` (structured bug report) and
`<bug_id>.result.json`.

### Bug Result Format

**`<bug_id>.result.json`:**
```json
{
  "id": "<bug_id>",
  "confirmation_status": "confirmed" | "not_confirmed" | "error",
  ...
}
```

**`<bug_id>.md`** (structured bug report sections):
- Specification Claim
- Actual Behavior
- Code Evidence (with line numbers)
- Trigger Condition
- How to Trigger (input params, expected vs actual output)
- Probe Script (full test script)
- Probe Output (raw stdout)

### Summary Aggregation

**`_generate_validation_summary(proj_dir)`:**
Scans `bug_validation/*.result.json`, writes atomically to `summary.json`:
```json
{
  "total_reported": N,
  "total_confirmed": N,
  "total_not_confirmed": N,
  "total_error": N,
  "bugs": [
    {"id": "...", "confirmation_status": "...", ...}
  ]
}
```
Sorts by: status order (confirmed→not_confirmed→error), then alphabetical by ID.

### `_spec_task_done(handle)` / `_spec_task_exit_code(handle)`

Abstraction over `subprocess.Popen` and `concurrent.futures.Future` for
normalizing spec generation subprocess exit status.

## Entry Points

### `streaming_reasoner(input_dir, output_dir, ...) → set[str]`
Main streaming reasoner. Returns set of processed file paths.

### `_verify_single_file(file_path, ...) → (str, str)`
Verifies one function file. Returns `(file_path, verdict)`.

### `_validate_single_bug(result_json_rel, proj_dir, ...)`
Validates a MISMATCH result via OpenCode bug validation agent.

### `_generate_validation_summary(proj_dir)`
Generates `bug_validation/summary.json`.
