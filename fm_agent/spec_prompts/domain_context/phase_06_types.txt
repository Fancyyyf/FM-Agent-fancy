# Phase 6: Alternative Pipeline Entry Points — Types and Invariants

## Overview

Phase 6 provides two alternative pipeline modes: entry-point-scoped reasoning
that traces the call graph from a user-specified entry function, and incremental
analysis that diffs against a previous run to re-analyze only changed/affected
functions.

## Key Types — Entry Pipeline (entry_reasoning_pipeline.py)

### Call Graph Restriction

**`_restrict_to_chains(call_graph, entry_func, end_funcs) → dict[str, list[str]]`:**
Returns only functions on call chains from `entry_func` to any `end_func`.
- Builds reverse adjacency (callers), reverse-BFS from end_funcs.
- Prunes to on-chain functions; end_funcs become terminal.
- If no chain exists: raises `ValueError`.

### Source-to-Function Mapping

**`_extracted_file_to_source_rel(extracted_rel) → str`:**
Inverse of extraction layout. Finds `<base>-<ext>` directory, converts to
`<base>.<ext>`. Example: `src/engine/loader-cpp/loadData.cpp` → `src/engine/loader.cpp`

**`_fqn_to_ident(fqn) → str`:**
Extracts class-qualified identifier from FQN tail after `<base>-<ext>` component.
`src::storage-cpp::LocalStorage::Flush` → `LocalStorage::Flush`

**`_entry_func_source_rel(entry_func) → str`:**
Maps entry FQN to source file: `src::engine::loader-cpp::loadData` → `src/engine/loader.cpp`

### Source Trimming

**`_trim_source_file(filepath, keep_names, proj_dir=None) → (int, int)`:**
Deletes function bodies NOT in `keep_names`. Uses `_function_spans` (codegraph
when proj_dir given, regex fallback). Preserves non-function lines. Returns
`(kept, removed)`.

**`_trim_project_in_place(proj_dir, all_by_source, keep_by_source)`:**
For each source: delete if no functions selected; otherwise trim in place.

### Entry Pipeline Core

**`run_entry_pipeline(proj_dir, entry_func, end_funcs, resume, domain_knowledge_files, one_phase, extra_call_edges_path, only_spec)`:**
1. **Selection**: Extract all functions to temp workspace, build call graph, BFS
   from entry, restrict to chains. Discard temp workspace.
2. **Copy**: Copy proj_dir to `<proj_dir>.fm-entry-run` (excluding .git).
3. **Trim**: Delete unrelated functions and source files from copy.
4. **Run**: Invoke standard `run_pipeline()` on trimmed copy.
5. **Copy-back**: Copy `fm_agent/` back to original proj_dir, discard run dir.

**Invariants:**
- `proj_dir` never modified; all mutations on run copy.
- Run directory removed after copy-back (even on failure, via finally).
- Bug validation retries set to 0 in entry mode.
- Entry function's source file exempted from test-file filtering.

### Selection Functions

**`_select_functions_by_source(proj_dir, entry_func, end_funcs, extra_call_edges) → (defaultdict, defaultdict)`:**
Returns `(all_by_source, keep_by_source)` mapping source rel → function idents.

**`_enumerate_source_files(proj_dir) → list[str]`:**
Lists all supported, non-test source files (skips fm_agent/ and .git/).

## Key Types — Incremental Reasoner (incremental_reasoner.py)

### Changed Function Detection

**`_collect_changed_functions(proj_dir, old_commit_id, submodules=None) → dict[str, dict]`:**
Returns per-absolute-path change info:
```python
{
    "/abs/path/to/file.py": {
        "added": ["new_func_1"],
        "removed": ["old_func"],
        "modified": ["changed_func"]
    }
}
```

Algorithm: git diff + ls-files, filter by extension/test/workspace, extract
functions from old commit and working tree, compare by source text.

**Invariants:**
- Functions compared by source text, not just name.
- New file: all functions marked "added". Deleted file: all marked "removed".

### Function Target Resolution

**`_modified_function_targets(proj_dir, modified_functions) → dict[str, str]`:**
Maps FQN → extracted file path. Handles bare names from regex detector by
walking function directory and matching by bare method tail.

### Spec Management

**`extract_existing_specs(proj_dir) → dict[str, dict]`:**
Captures [SPEC]/[INFO] blocks from all specced files before re-extraction:
```python
{"rel/path": {"spec": "<full [SPEC] block>", "info": "<full [INFO] block> or None"}}
```

**`_reapply_existing_specs(proj_dir, specs) → int`:**
Prepends captured headers onto re-extracted files. Skips already-specced files.
Returns number of files updated.

**`_update_specs_for_intent(proj_dir, work_dir, developer_intent, changed_functions, spec_files, extra_call_edges) → list[str]`:**
Re-generates specs for changed functions and intent-relevant functions. Uses
LLM calls to decide if [SPEC]/[INFO] needs updating, generate new text,
propagate callee changes to callers' [INFO] blocks.

### Validation Types

**`_validate_spec_update(data)`:**
```python
{"spec_updated": bool, "new_spec": str, "info_updated": bool,
 "new_info": str, "updated_callees": list[str]}
```
`new_spec` non-empty when `spec_updated`; `new_info` non-empty when `info_updated`.

**`_validate_caller_info_update(data)`:**
```python
{"info_updated": bool, "new_info": str}
```
`new_info` non-empty when `info_updated`.

**`_validate_module_selection(data)`:**
```python
[{"phase": int, "name": str}, ...]
```

### Scope Selection

**`collect_relevent_function_scope(proj_dir, developer_intent, changed_functions, range=None) → list[str]`:**

Three-pass narrowing:
1. **Module selection** — LLM picks relevant modules from descriptions.
2. **File selection** — OpenCode picks relevant files per module.
3. **Function selection** — `rank_functions_in_file` ranks by heuristic scoring.

Returns extracted function file paths (relative to `extracted_functions/`),
ordered by descending relevance.

### Incremental Pipeline Stages

```
[1/10]  Check previous full run existence
[2/10]  Load developer intent
[3/10]  Regenerate phases.json (incremental mode)
[4/10]  Re-extract functions and restore previous specs
[5/10]  Collect changed functions vs. base commit
[5b]    Delete stale extracted files for removed functions
[6/10]  Collect file list
[7/10]  Generate topdown layers
[8/10]  Collect functions relevant to developer intent (scope)
[9/10]  Update specs for changed and relevant functions
[10/10] Verify changed and affected functions
```

### `_verify_incremental_functions()`

Verifies functions where: (1) function changed, (2) spec updated, or (3) callee
spec changed. Then re-checks callers whose callee specs changed (propagation).

### `_StdoutTee`

Wraps `sys.stdout` to mirror `print()` output to both console and log file stream.

### `_setup_incremental_logging(work_dir) → str`

Configures per-run logging: FileHandler at `fm_agent/incremental_<timestamp>.log`,
StreamHandler to stdout, stdout tee for shared helpers' output.

## Entry Points

### `run_entry_pipeline(proj_dir, entry_func=None, end_funcs=None, ...)`
Entry-point-scoped reasoning. Traces call graph, trims project, runs pipeline on
trimmed copy, copies results back.

### `run_incremental_pipeline(proj_dir, intent_file_path, old_commit_id, ...) → list[str]`
Incremental analysis. Diffs against previous run, scopes to developer intent,
updates specs, re-verifies affected functions. Returns buggy file paths.

### `check_last_run_existence(proj_dir, submodules=None) → bool`
Checks whether a completed full pipeline run exists. Requires phases.json and
all extracted functions to have [SPEC]/[INFO] blocks.

### `collect_relevent_function_scope(proj_dir, developer_intent, changed_functions, range=None) → list[str]`
Three-pass scope selection: modules → files → functions.
