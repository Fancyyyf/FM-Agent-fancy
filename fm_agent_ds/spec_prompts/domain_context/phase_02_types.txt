# Phase 02 — Language Backend & Function Extraction

## Core Types

### `LanguageHandler` (dataclass)
```python
@dataclass
class LanguageHandler:
    """Extraction and call-graph backend for one language."""
    batch_extract: Callable   # (proj_dir) -> {abs_filepath: [(func_name, body)]}
    call_edges: Callable      # (proj_dir) -> {caller_fqn: {callee_fqns}}
    function_spans: Callable  # (proj_dir, filepath) -> [(func_name, start_idx, end_idx)] | None
```
- All three handlers manage their own backend (e.g., CodeGraph) internally
- `batch_extract` / `call_edges` return empty dict when backend unavailable
- `function_spans` returns None when backend unavailable — caller falls back to regex extractor
- Language keys: "python", "go", "c", "cpp", "java", "rust", "javascript", "typescript", "erlang"

### `REGISTRY` (dict)
Global dict mapping language key → LanguageHandler instance.
```python
REGISTRY: dict = {
    "python":     LanguageHandler(batch_extract=..., call_edges=..., function_spans=...),
    "go":         LanguageHandler(...),
    "c":          LanguageHandler(...),
    "cpp":        LanguageHandler(...),
    "java":       LanguageHandler(...),
    "rust":       LanguageHandler(...),
    "javascript": LanguageHandler(...),
    "typescript": LanguageHandler(...),
    "erlang":     LanguageHandler(...),
}
```

## Registry Entry Points

### `batch_extract_all(proj_dir) → tuple`
Merges results from all registered languages.
Returns `(funcs, langs)` where:
- `funcs`: `{abs_filepath: [(func_name, body_text)]}`
- `langs`: `set[str]` — language keys that returned non-empty data

### `call_edges_all(proj_dir, lang_keys) → tuple`
Merges call edges from specified language keys.
Returns `(edges, langs)` where:
- `edges`: `{caller_fqn_string: set_of_callee_fqn_strings}`
- `langs`: `set[str]` — language keys handled by CodeGraph (returned a dict, not None)

### `function_spans_for_file(proj_dir, filepath, lang_key) → list | None`
Returns `[(func_name, start_idx, end_idx)]` (0-indexed, inclusive) or None to fall back.

## CodeGraph Canonicalization

### `canonicalize(func_name) → str`
Returns filesystem-safe, FQN-safe function name.
- Translates `/` → `_` (handles C++ `operator/` etc.)
- Called by EVERY entry point that introduces a function name into the system

### `_extraction_ident(name, qualified_name) → str`
Returns class-qualified, filesystem-safe function identifier.
- Uses `_qualified_parts()` to split qualified_name by `::` or `.`
- Each part passed through `_bare_function_name()` then `canonicalize()`
- Joined with `::`
- Example: `("Flush", "LocalStorage::Flush")` → `"LocalStorage::Flush"`

### `_bare_function_name(name) → str`
Strips tree-sitter decorations (full signatures, template bodies) from name column.

## Supplemental Call Edges

### `CallerSelector` (frozen dataclass)
```python
@dataclass(frozen=True)
class CallerSelector:
    fqn: str                     # exact FQN for one caller; may be empty
    callsite_names: tuple[str, ...]  # source callsite function names
```
- At least one of `fqn` or `callsite_names` must be non-empty

### `CalleeTarget` (frozen dataclass)
```python
@dataclass(frozen=True)
class CalleeTarget:
    fqn: str                     # exact FQN for the callee
    info_names: tuple[str, ...]  # names for matching in .info.json sidecars
```

### `CallEdge` (frozen dataclass)
```python
@dataclass(frozen=True)
class CallEdge:
    caller: CallerSelector
    callee: CalleeTarget
    source: str = ""   # provenance string for diagnostics
```

### `load_call_edges(path) → list[CallEdge]`
Loads supplemental edges from a JSON file or directory of JSON files.
JSON format: `{"edges": [{"caller": {...}, "callee": {...}, "evidence": [...]}]}`

### `normalize_fqn_label(label) → str`
Converts `path/to/file.c::func` → FM-Agent FQN (`path::to::file-c::func`).

## Extraction Configuration

### `EXT_TO_LANG`
Maps file extensions to language keys used in `REGISTRY`.
```python
{".rs": "rust", ".c": "c", ".h": "c", ".cpp": "cpp", ".py": "python",
 ".java": "java", ".go": "go", ".js": "javascript", ".ts": "typescript",
 ".erl": "erlang", ...}
```

### `LANG_CONFIG` (per-language extraction config)
```python
{
    "cpp": {
        "comment_prefix": "//",
        "skip_prefixes": ("//", "#", "using", "typedef"),
        "skip_keywords_line": ("namespace", "struct", "class"),
        "keywords": {...},       # set of language keywords to skip
        "body": "brace",         # "brace" | "indent"
    },
    # ... per-language entries for c, python, go, rust, java, typescript, javascript
}
```

## Invariants

1. Function names in extracted files MUST be canonicalized — FQN components use `::` separator, unsafe chars translated.
2. Extracted function layout: `extracted_functions/<rel-source-dir>/<basename-ext>/<FuncName>.<ext>`
   where `<basename-ext>` replaces the last `.` in the source filename with `-` (e.g., `loader.cpp` → `loader-cpp`)
3. Member functions have class-qualified flat filenames: `loader-cpp/MyClass::method.cpp`
4. Call edge keys (both caller and callee) use the SAME canonicalized FQN scheme as extracted files.
5. `call_edges_all` returns BOTH the edges dict AND the set of languages handled by CodeGraph —
   the caller must not fall back to regex for languages CodeGraph already handled.
6. Registered language handlers must implement all three methods: `batch_extract`, `call_edges`, `function_spans`.
