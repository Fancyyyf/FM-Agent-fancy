# Phase 05 — Specification & Verification Utilities

## Core Types

### File Utilities (`file_utils.py`)

**Metadata Sidecar Schemas:**

**`.spec.json`** — Function behavioral specification:
```python
_SPEC_FIELDS = {"signature", "pre_condition", "post_condition"}
# All three must be present and be strings.
```

**`.info.json`** — Callee knowledge for reasoning:
```python
_CALLEE_FIELDS = {"name", "signature", "pre_condition", "post_condition"}
# Top-level: {"callees": [{name, signature, pre_condition, post_condition}]}
# Each callee dict must have exactly _CALLEE_FIELDS, all string-typed.
```

**File Readiness:** `is_file_ready(file_path) → bool`
A function is "ready" when BOTH sidecar files exist and pass schema validation.

**Test File Detection:** `_is_test_file(file_path) → bool`
Checks directory names (`test`, `tests`, `spec`, `t`, `__tests__`, etc.) and
file name patterns (`test_*`, `*_test.*`, `*_spec.*`, `*Test.*`, `*Tests.*`).

**Project Source File Iteration:** `_iter_project_source_files(proj_dir, submodules=None)`
Yields `(abs_path, rel_path)` pairs for all source files in the project,
filtering out test files and respecting `--submodule` boundaries.

**Submodule Filtering:** `_is_under_submodules(rel_path, submodules) → bool`
Returns True when `rel_path` is under one of the submodule directories.

**File Name Collection:**
```python
def collect_file_names(input_dir, output_path="file_list.json") → list[str]:
    """Collect and write sorted, deduplicated relative file names to JSON."""

def _write_file_names(file_names, output_path) → list[str]:
    """Write sorted, deduplicated file names atomically (tmp+rename)."""

    """Collect all extracted function files across all phases."""

    """Collect files for one phase/layer. Returns [(file_path, module_name)]."""

    """Return files pending verification (reasoning output not yet produced)."""
```

### Spec Parser (`parser.py`)

**`FunctionSpecMap` (dict subclass):**
```python
class FunctionSpecMap(dict):
    def __init__(self):
        super().__init__()
        self.signatures: dict = {}  # function_name → signature string

    def add_entry(self, function_name, signature, spec) → None:
        """Store function_name → spec_text, and its signature."""
        self[function_name] = spec
        self.signatures[function_name] = signature

    def __str__(self) → str:
        """Format as newline-separated entries: '<signature>\n<spec>'"""
```

**Spec Formatting:**
```python
def format_spec_for_reasoner(spec: dict) → str:
    """Rebuild reasoner-facing spec text from .spec.json object.
    Output format:
        <signature>
        
        Pre-condition:
        <pre_condition_text>
        
        Post-condition:
        <post_condition_text>
    """

def format_info_for_reasoner(info: dict) → FunctionSpecMap:
    """Rebuild callee specs from .info.json object.
    Each callee formatted as:
        Pre-condition: <callee_pre_condition>
        Post-condition: <callee_post_condition>
    """

def parse_input_function(file_path) → tuple:
    """Parse function source file for reasoning.
    Returns (code_text, spec_dict, info_dict, function_name).
    Uses _load_sidecar_json and _remove_func_comments."""
```

**Sidecar Loading:**
```python
def _load_sidecar_json(file_path, suffix) → dict | None:

def _remove_func_comments(code) → str:
```

## Invariants

1. **Sidecar validation**: `.spec.json` must have exactly `{"signature", "pre_condition", "post_condition"}`;
   `.info.json` must have exactly `{"callees": [...]}`, each callee with exactly
   `{"name", "signature", "pre_condition", "post_condition"}`.
2. **All values in spec/info JSON are strings** — no nested objects, no arrays as field values.
3. **`is_file_ready` is the single gate for reasoning** — if it returns False, the function
   is skipped by both spec generation and verification.
4. **`FunctionSpecMap.__str__()`** is used to feed callee knowledge to the reasoner prompt —
   its formatting MUST match the reasoner's expected input format.
5. **Batch prompts preserve dependency ordering** — callee specs are included before
   the caller function's prompt text, ensuring the LLM has callee knowledge available.
6. **`_remove_func_comments` respects string literals** — it must not strip content inside
   `"..."` or `'...'` strings, even if they resemble comment syntax.
7. **File name collections are always sorted and deduplicated** before writing.
